# 恢复模型与证据边界

## 先区分两种问题

1. 保存的项目目录、账号项目清单和映射完整，只有正在显示的窗口为空：可能是窗口初始化/状态刷新问题。写文件不一定有帮助。社区在 macOS 的三账号场景观察到 File → New Window 恢复；没有证明 Windows 或所有版本均有效。
2. 数据库仍有项目，而当前账号 `local-projects` 为空或不完整：可以考虑恢复明确缺失的注册记录。应用运行时会持有内存状态，因此离线应用修复，不强行实时改文件。

来源：[Windows 侧栏缓存恢复案例](https://github.com/openai/codex/issues/54538)、[账号切换问题与最新窗口绕行报告](https://github.com/openai/codex/issues/59895)。这是社区观测，不是官方恢复协议。

## 身份与归属

读取当前 JSON（可加一份用户选择的历史 JSON）及 SQLite 的只读事务快照。项目 ID 来自明确的保存映射、数据库 `codex.localProjectId`、唯一 UUID 幂等键或既有数据库身份。多种身份相互冲突时不推断。

已有项目必须与数据库根目录一致且根目录可访问。遇到同根目录、不同身份的既有项目，保留它并报告冲突，暂不自动合并或改 ID。

聊天归属仅使用数据库已有 `project_id` 或保存的明确关联。相互矛盾、当前标记为无项目、缺少线程或会话文件的记录不会被新增到目标账号。不会凭 `cwd` 自动归类，包括 worktree 和嵌套目录。

带云端关联的项目保留原样、不迁移。仅删 JSON 中的云端关联可能被后台从数据库重新补回，不能当成可靠的解绑操作。

## 写入边界

允许修改的字段只有：

- `local-projects`
- `app-server-project-id-by-legacy-project-id-by-host`
- `project-order`
- `thread-project-assignments`
- `thread-project-membership-host-ids`

范围为用户选择的当前账号，或执行时本机保存的所有账号。登录身份、账号偏好、云端数据、权限及迁移标记不变。没有活动账号时只能明确选择所有已保存账号，不伪造账号身份。

预览绑定当前 JSON、其 `.bak`、数据库相关记录及可选历史状态指纹。实际写入前重新扫描；任何影响计划的变化都要求重新预览。仅在受支持的应用版本且相关进程已退出时允许写入。进程检查不确定时拒绝写入。

## 备份与撤销

备份放在 Codex 数据目录之外，包含两份 JSON 的原始字节、通过 SQLite backup API 取得的一致性数据库快照、候选 JSON、字段差异及校验值。

候选内容写入临时文件、刷新后分别替换主 JSON 和 `.bak`。第二次写入失败时尝试还原先前文件。两个文件并不是一个原子事务，断电、磁盘故障或回滚失败需要使用保留的备份恢复。

撤销通过账号标识找到对应的项目字段，而不是把整个旧配置覆盖回来。因此，账户从活动状态移到 inactive 或其他普通设置变化时可以保留这些变化。被恢复的项目字段本身若已有变化，则拒绝自动撤销，避免删除后续新项目或新聊天关联。

状态文件写入完成、打开应用能看到项目、旧聊天可以读取、再次切换账号仍然存在，分别是不同的验证阶段。工具只确认自己完成的文件读写，不自动报告“已永久修复”。

## 兼容性

当前 `0.1.0a2` 预览包向 `26.1103.4239.0` 和 `26.1103.7773.0` 开放写入。适配基于 Windows 安装包的账号状态、项目结构、身份映射和初始化逻辑检查，以及合成数据的备份、写入和撤销验证。详见[适配依据与验证边界](compatibility.md)。这不等于实际侧栏和旧聊天已经验证恢复；仍需用户核验。未知版本可以扫描，不能绕过写入限制。

同一 Windows 用户下多账号可共享本地项目的产品语义仍有讨论；本工具只在用户明确选择所有账号时同步普通本地注册记录。它不是账号隔离策略修改器，也不把其他人的账号数据设成默认共享。
